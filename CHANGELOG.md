# Changelog

All notable changes to `highcharts-editable-excel` are recorded here. The project uses semantic
versioning; see "Stability and versioning" in the README for what is covered.

> **From now on this file is generated by [Changesets](https://github.com/changesets/changesets).**
> Do not edit it by hand: each pull request that changes the package adds a changeset
> (`pnpm changeset`), and `pnpm run version` (`changeset version`) writes the release section.
> Before the first `pnpm run version`: check that every bullet under `Unreleased` is covered by a file
> in `.changeset/` (the list below is captured in `.changeset/stable-public-surface.md`), then
> delete the `Unreleased` section and move this note above the release section, which Changesets
> inserts directly under the `# Changelog` line while the file has no version heading.

## Unreleased

- Export a live Highcharts chart, or a plain options object, to an `.xlsx` workbook holding a **native Excel chart** whose series reference cells on a data sheet (`exportHighchartsToXlsx`, `exportHighchartsOptionsToXlsx`, `downloadHighchartsAsXlsx`).
- Context-menu integration: `installHighchartsExcelExport(Highcharts)` adds a "Download editable Excel chart" item to every chart, with per-chart `exporting.editableExcel` options and `addEditableExcelMenuItem` for already-rendered charts.
- Menu customization in `InstallOptions`: `langKey` (the item is defined with `textKey`, so `Highcharts.setOptions({ lang: { downloadEditableXLSX: '…' } })` translates it; text order: per-chart `menuText` → install `menuText` → `lang[langKey]` → `DEFAULT_MENU_TEXT`), `menuIcon` (`'excel'`, `{ svg }`, `{ html }`; per chart via `exporting.editableExcel.menuIcon`), `button` (context-button symbol, colors, theme, title, and a custom `svgPath` registered as a renderer symbol) and `menuStyle` / `menuItemStyle` / `menuItemHoverStyle`. `uninstall()` restores every global option it changed. New exports: `MENU_ICON_EXCEL_SVG`, `DEFAULT_LANG_KEY`, `DEFAULT_BUTTON_SYMBOL` and the `ContextButtonOptions`, `MenuIconOption`, `MenuCssOptions` types; `Installation` gains `langKey` and `menuItemKey`.
- Behavior change: without `menuText`, the global item definition has no `text`; its text comes from `lang.downloadEditableXLSX` (registered with the default text at install when absent).
- Chart types: line, spline, area, column, bar (stacked and percent), scatter, bubble, pie, doughnut, and column/line combos with secondary axes; datetime, logarithmic, reversed and opposite axes.
- Styling carried over where Excel can express it: series and point colors, gradients, dash styles, markers, fonts, data labels, legend position, axis number formats; `themeOverrides` and `hooks.transformModel` customise the result.
- Diagnostics for everything that is approximated, unsupported or blocking (`analyzeChartCompatibility`, `onWarning`, `strictMode`, `ExportError` codes); missing data stays empty and is reported, never fabricated.
- Multi-chart workbooks (`exportChartsToWorkbook`) and an optional PNG reference image next to the native chart (`includeReferenceImage`).
- Chart.js 4 adapter (`highcharts-editable-excel/chartjs`): `exportChartJsToXlsx`, `downloadChartJsAsXlsx`, `analyzeChartJsCompatibility` and `extractChartJsModel` accept a live `Chart` instance or a plain `{ type, data, options }` configuration (line, bar, stacked/horizontal bar, pie, doughnut, scatter, bubble, mixed bar + line, time/log/secondary scales; radar and polarArea are reported as not editable). `chart.js` is an optional peer dependency; `ChartMeta.sourceLibrary` is now `'highcharts' | 'chartjs'`. See `docs/chartjs.md`.
- Large charts stay responsive. The built-in writer serializes worksheet cells and chart caches in chunks and, in browsers, yields to the event loop between them; in browsers the package is zipped by fflate's worker-based `zip` (`zipSync` in Node and jsdom, or when a CSP forbids `blob:` workers), with byte-identical output. New `ExportOptions.signal` (rejects with the new `ExportError` code `ABORTED`, `cause` = `signal.reason`; `downloadHighchartsAsXlsx` does not download after an abort) and `ExportOptions.onProgress` (`ExportProgress`: phase `extract` / `translate` / `write` / `zip` / `done` and a monotonic overall `fraction`), also accepted by `exportChartsToWorkbook`'s second argument. `ExportTimings.zipMs` (part of `writeMs`). `ExcelWriter.write` takes an optional second `WriteContext` (`signal`, `onProgress`, `yieldEvery`); `createDefaultExcelWriter({ zip: 'sync' | 'async' | 'auto' })` picks the zip path. `pnpm bench` adds 100,000-point cases and the longest event-loop stall ("max tick gap") for both zip paths. Streaming export is not implemented.
- Data modes: `rendered` (what the chart shows, including Stock grouping and cropping) and `raw` (the source `options.data`).
- Own narrowly scoped OOXML writer on `fflate` behind the `ExcelWriter` interface; a custom writer can be passed via `ExportOptions.writer`. All cell text is written as inline strings (formula-injection safe).
- ESM only, Highcharts as a peer dependency (tested against 11.4.9, 12.6.2 and 13.1.1), no runtime dependencies.
- Fidelity backlog: polar line/spline/area charts export as native Excel **radar** charts (marker, standard or filled; polar columns stay blocking). `errorbar` series become custom Excel **error bars** on their linked parent series (`+err` / `-err` data columns). `columnrange` / `arearange` export as stacked columns/areas with a hidden base series; the data sheet holds Low, High and a Range column of library-generated formulas (`=High-Low`, or MAX/MIN Base/Up/Down helpers when a column range crosses zero) so editing Low/High updates the chart. Doughnut rings whose slices differ get their own category columns (no more `APPROXIMATED_LAYOUT` union). `lang.thousandsSep` / `lang.decimalPoint` are now read and raise `APPROXIMATED_NUMBER_FORMAT` once per chart when a format groups digits or shows decimals with a different separator. Per-chart menu settings are re-applied after `chart.update({ exporting })`. New `ThemeOverrides.cssVariables` resolves styled-mode colors headless. IR: `SeriesKind` gains `errorbar`, `columnrange`, `arearange`; optional `SeriesModel.linkedTo`, `PointModel.low/high`. Writer: `CellValue` `{ type: "formula" }` (library formulas only; the writer rejects anything else), `PlotGroupSpec` kind `radar`, optional `ExcelSeriesSpec.errorBars`.
- Validated structurally, by an `@office-kit/xlsx` round-trip and by LibreOffice renders; not yet opened in Microsoft Excel (see `docs/manual-qa.md`).
